# 自動運用の仕様

Cloudflare Cron から `runAutomation` を呼び出します。処理は UTC 日付ごとに一度だけ実行します。日本時間の表示日と日次ロックのキーは異なることがあります。管理画面の手動実行も同じ日次ロックを共有します。

基本運用はGoogleの自然検索を中心にします。毎日の情報源・広告・計測の点検を、毎日の新記事作成やSNS運用の義務とは扱いません。検索で表示された疑問と既存ページの不足を確認し、既存記事の改善を優先します。記事生成を止めても、点検と改善案の評価は続きます。

## 自動で行うこと

1. 400 日より古い日別の診断・広告クリック集計を削除します。登録した広告の期限と HTTPS・許可ホストを検査し、不正または期限切れの広告を無効にします。ASP の計測 URL への自動アクセスは行いません。広告クリックを水増ししないためです。
2. 詳細な訪問・クリック記録の90日保持処理と、需要・集客・成約の評価を行います。鮮度・母数・成果照合条件を満たした仮説があれば、対象読者と具体的な課題を次の記事のテーマとして優先し、理由と改善案を記録します。評価失敗は履歴に記録し、既存の編集計画へ戻ります。条件に達する仮説がなければ、過去 30 日の用途別診断を集計します。同じ用途が 30 件以上選ばれた場合は、その中で最も多い用途の情報源を優先します。該当する道具が一つだけなら、情報整理・文章作成の道具を補完に使います。十分な件数がなければ日替わりで二つの情報源を選びます。選択理由・対象用途・件数・情報源は実行履歴の editorial に残し、広告報酬で読者向けの順位を変更しません。選んだ公式サイトの情報源を確認します。robots.txt に従い、取得失敗・許可されないリダイレクト・長すぎるレスポンス・本文が短すぎるページは採用しません。結果と本文ハッシュを D1 に記録します。
3. Workers AI が有効な場合、両方の情報源の取得が成功したときだけ、取得した本文を材料に独自の日本語ガイドを一つ作成します。生成量は設定値にかかわらず最大一日一記事です。日ごとにテーマを切り替え、既存記事と同じ題名や段落が多い出力は不採用にします。存在しない機能や古い料金を推測して書かせません。
4. JSON の構造、長さ、引用の実在、公式情報源の対応、注意点の有無、禁止表現を検査します。料金・無料プラン・成果保証・個人の実体験・数値性能・外部リンクを含む出力は不採用にします。
5. `ENABLE_AUTOPUBLISH=true` の場合だけ合格した記事を公開します。初期設定は false です。false では下書きとして保存します。記事の最低長や根拠に達しなければ、公開数を埋めるために条件を緩めません。
6. SNS用の下書きは既定で作りません。`ENABLE_SOCIAL_DRAFTS=true`を明示した場合だけ、既存記事から短い下書きを実行履歴に保存します。Threadsなどへの投稿・送信は行いません。

## 必要な設定

- D1: マイグレーションを適用した DB バインディング。
- Workers AI: `AI` バインディング。モデル `@cf/meta/llama-3.3-70b-instruct-fp8-fast` を使用します。アカウントで利用できることと費用を確認してください。AI がない環境では情報源と広告の点検だけを行い、生成は skipped と記録します。
- `ENABLE_AUTOPUBLISH`: 初期値 false。合格した生成物を自動公開する場合は true。
- `ENABLE_SOCIAL_DRAFTS`: 初期値 false。必要な施策としてSNSを検討するときだけtrueで下書きを作成。投稿機能はありません。次回デプロイ時に省略した場合もfalseとなり、以前の有効設定を残しません。
- `MAX_DAILY_ARTICLES`: 初期値 1。0 で記事生成を停止します。1 より大きくしても一日一記事を上限にします。

公式サイトの本文は外部から取得したデータとして扱い、その中の命令には従わせません。情報源の取得は HTTPS に限定し、既知の公式ホストだけを許可します。同じホスト内のリダイレクト以外は追従しません。本文は最大 160 KB、モデルへ渡す本文は情報源ごとに最大 9,000 文字です。HTTP 取得は一回につき最大 8 秒です。AI の応答待ちは 45 秒で打ち切り、その実行からの記事公開は行いません。待機の終了は AI プロバイダー側での推論キャンセルを保証しないため、モデルの出力トークンも最大 3,600 に制限しています。

## 実運用の限界

取得成功と引用一致は、記事の全記述が正しいことを証明しません。自動検査は補助であり、初期は下書きの品質を確認してから自動公開を有効にしてください。料金・プランの網羅的な最新保証や、サービスを実際に利用したレビューは提供しません。リンク先で仕様を確認する導線を維持します。

日次ロックは重複公開と無制限の AI 費用を防ぎます。処理が停止した場合もその日の自動リトライはせず、次の日に再開します。失敗・スキップは管理画面の実行履歴に表示します。緊急時は `MAX_DAILY_ARTICLES=0` とし、原因を確認してください。

売上は ASP で承認された成果を別途連携したものだけを計上します。アクセス数、広告クリック、推定報酬から売上を作りません。ASP 審査・提携・広告の承認・ドメイン・Cloudflare 認証は所有者による初期設定が必要です。これらの未設定や、アクセス・成約がない状態を「収益化済み」とは表示しません。

需要根拠の登録、計測の範囲、改善判断の運用上の目安、変更後の再評価は[GROWTH.md](GROWTH.md)を参照してください。改善案はAI未接続でも作成します。記事の生成・公開は既存のAI接続・情報源・品質条件を満たす場合に限ります。
