# 検索意図に合わせた記事・比較ページの計画

2026-10-28時点の編集仮説です。外部の検索データは通信制限により未取得で、検索数・競合難易度・成約率は未検証です。現行カタログの用途と、読者が選ぶ際に比較できる条件から候補を作っています。

## 先に整えるページ

| 優先 | 想定する検索語 | 読者が決めたいこと | 対応ページ・作業 | 次の行動 |

| 1 | Canva Adobe Express 比較 | 資料・画像・動画の制作と共同編集に合う候補 | 既存 `/guides/canva-adobe-express` と専用比較ページ。素材の利用条件・書き出し・共同作業を整理 | 機密でない同じ制作物で試す |

専用比較ページは `/compare/make-vs-zapier`、`/compare/canva-vs-adobe-express`、`/compare/chatgpt-vs-claude` に実装済みです。自由な候補の組み合わせは `/compare` から選べます。価格・無料枠の最新性は、確認せずに表へ埋めません。

## 記事に必要な材料

各ページに、対象読者と具体的な作業、比較基準、向いている条件、向かない条件、公式の確認先、実際に試す手順を置きます。関連する比較と診断へ内部リンクを設けます。自分たちが行っていない利用体験や、存在を確認していない提携を記事の根拠にしません。

検索語の表記を増やすだけの重複ページは作りません。「料金」「無料」を検索語に加える場合は、公式ページの日時付き確認と更新体制が必要です。確認できるまでは料金を調べるためのチェック項目として扱います。

## 公開後に検証すること

Search Consoleの所有権確認後、ページ別のインデックス状態、実際に表示された検索語、表示回数、クリック、掲載順位を確認します。検索語ごとに情報を探している段階か、候補を比較している段階かを読み取り、タイトルと本文が同じ疑問に答えているか点検します。少ないデータから順位や収益の因果を断定しません。

サイト側では診断の用途別件数、広告クリック、ASPの確定成果を別々に記録します。診断件数と広告クリックは個人の一連の行動を追跡するファネルではなく集計値です。直接のページ閲覧や離脱は現時点のイベント設計で測定していないため、測定済みと説明しません。

公開後の最初の確認順序は、インデックス可能か → 意図した検索語で表示されるか → 記事から比較・診断へ進めるか → 有効な広告へ案内できるか → 確定成果が届くか、です。確認できた課題に対応して更新し、記事数や生成頻度だけを増やしません。
