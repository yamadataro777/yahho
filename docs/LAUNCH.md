# 公開のために残っている設定

コードの実装とローカル検証は、Cloudflare・ASP の接続前でも進められます。外部アカウント、公開情報、契約条件は所有者から供給される必要があります。現在は公開や提携を完了した状態ではありません。

## 運営者と問い合わせ先

公開用の設定に次を指定します。これらはサイトに表示する公開情報で、秘密値ではありません。

| 設定 | 内容 |
| --- | --- |
| `OPERATOR_NAME` | 実際に運営する個人・法人・屋号などの公開名称。100文字以内。架空の運営者名は生成しません |
| `CONTACT_EMAIL` | 運営者が確認できる問い合わせ用メールアドレス。表示名や `mailto:` は付けず、アドレスだけを指定 |
| `PUBLIC_CONTACT_URL` | メールの代わり、または追加で使用する運営者の公開問い合わせフォーム。公開HTTPS URLを指定 |
| `GOOGLE_SITE_VERIFICATION` | 任意。Search Console が発行したHTMLタグの `content` 属性の値だけを指定 |

公開前チェックは、運営者名と少なくとも一つの有効な問い合わせ先を要求します。メールは一般的な英数字・ピリオド・ハイフン・アンダースコア・プラス記号を使う形式に対応します。`example.com` などの例示用ドメイン、ローカル・プライベートホスト、メールヘッダーを追加する形式は受け付けません。設定がない状態で架空のメールアドレスや問い合わせ窓口を公開しません。

入力検証は形式の確認です。メールが実際に受信できることや、フォームを運営者が所有していることは証明しません。公開前に所有者が受信と問い合わせ先の表示内容を確認してください。

## Cloudflare と独自ドメイン

README の公開手順に従い、対象アカウントに限定したAPIトークン、アカウントID、D1 IDまたは初回作成指定、公開URL、管理用・成果連携用の別々の秘密値を設定します。

`npm run deploy -- --check` は外部変更なしで不足設定を確認できます。値の代わりに不足する設定名だけを報告します。実際の公開は、その後の明示的なデプロイコマンドで行います。

独自ドメインはDNSとWorkerルートの設定が別途必要です。`SITE_URL` に文字列を設定するだけではドメインの取得・接続は行われません。Cloudflareの設定後は、公開URLでヘルスチェック、主要ページ、問い合わせ先、広告表示を確認します。

## 検索からの流入

Search Console は所有者のアカウントでサイトを登録します。URLプレフィックスのHTMLタグ方式を使う場合に `GOOGLE_SITE_VERIFICATION` を設定できます。ドメインプロパティを使う場合は、Search Console の指示に従ってDNSで所有権を確認します。確認操作とサイトマップ送信は、登録後の所有者側の手順です。

公開サイトでは `/robots.txt` と `/sitemap.xml` を確認し、検索エンジンへのサイトマップ送信後に表示回数・検索語・クリックを観測します。所有権トークンの設定やサイトマップの存在だけでは、検索への掲載・流入・売上は保証されません。

## 広告と自動運用

広告は提携承認後、ASPから発行された実際のリンクを管理画面に登録します。情報サイトの掲載許可・広告表記・利用可能な文言・リンク改変の扱いを、その案件の規約で確認します。成果の確定・取消・通貨・通知署名などは、利用するASPに合わせて連携する必要があります。

Workers AI は本番アカウントに接続した後に検証します。公式情報取得、生成した下書き、公開条件を確認し、必要な場合に自動公開を有効にします。生成停止は `MAX_DAILY_ARTICLES=0`。この停止設定は再デプロイにも引き継がれます。詳しくは [自動運用仕様](AUTOMATION.md) を参照してください。
